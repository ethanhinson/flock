Run one language model split across your laptop and your phone.

Your phone's GPU actually computes four transformer layers. Activations cross your wifi. It is a real, if small, distributed inference system — about 600 lines you can read in a sitting.

Twenty-eight layers. Each bird is one.
    Hover a bird to see which layer it is. Click the sky and another device's birds join. Tap the sky and another device's birds join.

    The idea in one paragraph

    A transformer is a stack of identical layers. Token ids become a hidden state of shape [batch, seq, hidden]; each layer reads that tensor and writes one the same shape. So you can cut the stack anywhere, put layers 0–23 on one device and 24–27 on another, and ship the hidden state between them.

    The tensor is kilobytes; the weights are hundreds of megabytes. That asymmetry is the entire trick — it is why a phone can hold a slice of a model it could never download in full.

    The sky above is the same picture, with five devices on the wifi. Every bird is one layer. The geese are this Mac, flying the first twelve layers in a V; the other sixteen are split by measured speed across the swallows, the swifts, the gulls and the herons, each a different device holding a different share. The dotted line is the pipeline. The small ion running along it is the hidden state, and every time it reaches the head one word is written. Let a device join and the tail is re-split among the flocks. Let one leave and the writing stops, naming the layers nobody holds.

    Measured on real hardware

    19.6 tokens per second — an M3 Max and an iPhone on the same wifi, Qwen3-0.6B split 24/4

    decode, averaged over 59 tokensms
    coordinator · 24 layers · Deno + WebGPU19.6
    phone · 4 layers · WGSL in Safari15.4
    roundtrip including the network26.4
    network overhead, WebRTC data channel11.0
    wire per token · f16 binary (21.0 KB as JSON)2.0 KB

    The phone runs 4 of 28 layers and spends nearly as long as the coordinator's 24 — that asymmetry is what real heterogeneous hardware looks like. Under the original long-polling, fp32-JSON design the network cost about 132 ms per token. It is now 11.

    How it moves

    f16 frames over WebRTC

    The coordinator is itself a WebRTC peer. It offers each bird a data channel over the websocket; once that opens, the socket carries nothing but signaling. One wire format, one file, imported by server and browser alike.

    Weights straight from HuggingFace

    No build step, no export, nothing on disk. A GGUF's first few megabytes are a directory of byte offsets, so each device range-fetches its own layers — four layers of Qwen3-0.6B is 66.9 MB in one HTTP request.

    Streamed into the GPU

    Nothing ever holds a tensor in JS. Each 4 MB chunk goes into its GPU buffer as it arrives. Streaming four layers costs less heap than holding one, which is the difference between a phone that joins and an iPad that dies.

    The KV cache is sharded too

    Each device caches K/V for only its own layers, in GPU memory, never marshalled. Turn two feeds only the new tokens. No single device holds the conversation.

    Nine WGSL kernels, validated

    Q8_0 and Q4_0 matvecs, RMSNorm, RoPE, SwiGLU, attention — bit-exact or within a few ULP of a strict-f32 reference, and the whole model matches ONNX token for token.

    The split is decided live

    No device count to configure. The coordinator re-splits across whoever is present, by measured speed and real GPU limits, and says in words when a tensor will not fit before anything downloads.

    Read this before drawing conclusions

    • This is slower than either device alone. Pipeline parallelism buys capacity, not throughput. Only one node computes at a time — let a second phone join above and watch the ripple wait behind the slow flock.
    • No auth, no TLS, barely any input validation. LAN-only toy. Do not expose it to the internet.
    • No re-sharding on peer loss. If a device leaves, generation stops with a message naming the uncovered layers and resumes when some device claims that slot.
    • One conversation, no batching, no concurrency. A second simultaneous chat is refused rather than interleaving writes into the same K/V cache.

    Run it

    cd node && npm install && npm start     # runs Deno: the coordinator needs a GPU

# phone       http://<your-ip>:8000/flock    tap "join the flock"
# any browser http://<your-ip>:8000          chat

npm run solo      # no phone handy? every bird in one process
npm test          # syntax, range planning, the bird's load path

    Deno, not Node, and that is a requirement: Node has no WebGPU. Two phones? Open /flock on the second one and tap join. Everything else is decided while it runs.
